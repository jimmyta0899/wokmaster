# P2-3 离线实施与验证记录（2026-11-28，INBOX v7）

## 1. 原始现状（动手前复现）

在源码工作区 `E:\data\2026-10-15-11-35-18\wokmaster_source\web_preview` 复现确认：

- `web/flutter_bootstrap.js`：`_flutter.loader.load({ serviceWorkerSettings: null, ... })`
  —— service worker 被显式禁用。
- `web/index.html`：有 self-heal 脚本，检测到 `serviceWorker.controller` 就
  `getRegistrations() → unregister()` + `caches.delete()` + reload。
- `web/` 无 service worker 缓存逻辑；`build/web/flutter_service_worker.js` 是
  Flutter 3.47 SDK 模板生成的 **unregister-only** worker（activate 即自我注销）。
- 结论：与 INBOX v7 描述一致，离线确为主动关闭状态。

## 2. 关键SDK事实（决定方案，避免走弯路）

查 Flutter 3.47 SDK 源码确认（不是猜测）：

- `flutter_tools/lib/src/web/file_generators/flutter_service_worker.js` 模板内容
  **只做 unregister + reload，不缓存任何资源**；`generateServiceWorker()` 即使
  `offlineFirst` 也只返回这个模板。Flutter 已把 app shell 缓存职责外移
  （见 SDK 注释 https://github.com/flutter/flutter/issues/156910）。
- `--pwa-strategy` 已废弃；`kServiceWorkerStrategy` 默认 `offlineFirst`，只影响
  bootstrap 里 `serviceWorkerSettings.serviceWorkerVersion` 的注入（一次构建一个
  随机版本号，URL 加 `?v=` 防陈旧），不改变 SW 正文。
- build 会从 web/ 复制资源，但**过滤掉自定义 `flutter_service_worker.js`**
  （web.dart:1031）并用 SDK 模板覆盖（1045 行）——放自定义 SW 文件无效。
- `serviceWorkerVersion` 注入值自带引号与 deprecated 注释，模板写法必须是不带
  外层引号的 `serviceWorkerVersion: {{flutter_service_worker_version}}`。

结论：真正能落地的"离线看已存菜谱" = **Dart 层数据缓存**（已看过的内容存本机，
断网用同一套 fromJson 还原）；SW 只做合规启用与版本失效，不谎称它能缓存整站。

## 3. 改了什么（一次一处，改完即测）

### 改动 A：数据缓存层（核心离线能力）
- 新增 `lib/core/services/offline_cache.dart`：用 shared_preferences 存/读
  菜谱详情的原始 JSON，key = `wm.offline.recipe.<slug>`；读写异常全吞，
  缓存失败绝不影响在线主流程，无缓存绝不伪造数据。
- 改 `lib/data/repositories/recipe_repository.dart`：
  - 把 `fetchRecipeDetail` 的解析逻辑抽成 `static detailFromRaw(...)`，
    在线与离线共用同一套解析 + 过敏原过滤（避免两套逻辑漂移）；
  - 在线成功后把 recipe/ingredients/substitutes/steps 原始 JSON 写入缓存；
  - `catch`（含断网/超时）先读缓存还原，无缓存才抛 `RecipeRepositoryException`。
- 新增 `test/offline_cache_test.dart` 4 项：round-trip 不丢字段 / 无缓存返回 null /
  从缓存还原数值一致 / 离线还原也尊重过敏原硬过滤。

### 改动 B：Service Worker 合规启用
- `web/flutter_bootstrap.js`：`serviceWorkerSettings: null` 改为 SDK 格式
  `{ serviceWorkerVersion: {{flutter_service_worker_version}} }`；保留 local
  CanvasKit 配置（不走 gstatic，避免重演 P0 首帧卡死）。
- `web/index.html`：移除与启用冲突的"注销全部 SW + 清缓存 + reload"自愈脚本
  （保留一个说明性注释），避免"注册→注销→reload"循环。
- 中途发现并修复一次自身引入的 P0 回归：初版把版本占位符用单引号包裹，
  SDK 注入值里的 `Flutter's` 单引号截断字符串 → `SyntaxError: Unexpected
  identifier 's'` → app 白屏。改为不加外层引号后 `node --check` 通过、
  浏览器 boot 消失、`__wmBootDone` 正常调用，**回归排除**。

  占位符残留 0、旧注销脚本残留 0、`node --check flutter_bootstrap.js` 通过。
- 真实 Chrome（headless + CDP）本地构建实测：首帧 boot 屏消失（bootGone=true）、
  `__wmBootDone` 调用、无 error 级异常 —— **P0 首帧未回归**；断网后 SPA

### 未验证（诚实记录，不写"已完成"）
- **真实菜谱的断网内容渲染**：本地构建无 `SUPABASE_URL/ANON_KEY` dart-define，
  详情页在数据请求阶段由 provider 抛 `Bad state: Supabase 未配置`（发生在
  repository 的缓存 catch 之前），因此浏览器端到端看不到"从缓存还原的菜谱"
  内容。生产构建有配置时，断网请求抛网络异常会进入 `fetchRecipeDetail` 的
  catch → 读缓存 → `fromJson` 还原（代码路径已逐行确认），但**未在真机/线上验证**。
  缓存还原的正确性由 `offline_cache_test.dart` 4 项单测覆盖。
- **断网冷启动**（关页后断网重开）：Flutter 3.47 内置 SW 不缓存 app shell，
  断网后 HTTP 服务不可达时浏览器直接显示 Chrome 离线页。当前实现不支持
  "断网冷启动"，只支持"app 已加载后断网看已缓存的菜谱"。若验收要求冷启动，
  需要单独的 app shell 缓存方案（如手写 precache SW 并解决 build 覆盖问题），
  属新增方案，**未自作主张实施**，等 Muse/Jimmy 定夺。
- 线上 + 真机 + 真实数据集端到端：部署属红线，须 Jimmy 点头。
