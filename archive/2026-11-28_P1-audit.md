## 二、逐项详述

### 1. 每步都有照片/视频 —— 部分有
- 模型字段齐全：`RecipeStep.imageUrl` / `doneStateImageUrl`（切配完成图） / `videoUrl`
  （`lib/data/models/recipe_step.dart:16-18`）。
- 详情页渲染：`_steps()` 取 `_stepImage(s.imageUrl)`、`_stepImage(s.doneStateImageUrl)`，
  视频仅认 `http` 开头（`recipe_detail_page.dart:928-946, 996-1000`）。
- 但：步骤图有严格白名单"只认一图一步、全库唯一的两类来源"（`recipe_detail_page.dart:1228-1232`），
  且步骤图 2026-10-31 起迁到独立图床仓库 wokmaster-steps（`:1232-1233`）。
  注释明确记录数据问题："recipe.video_url 有 1475 行指向同一个 soup 视频（导入填充错误）"（`:39`）。
- 结论：能力具备，但**"每步都有"的覆盖率未被验证**；视频数据存在批量错误填充。
  需要抽样 N 道菜谱统计 imageUrl/videoUrl 非空比例才能定级为"有"。

### 2. 真正的 cook mode（屏幕常亮 + 命名计时器）—— 部分有
- 烹饪模式本体扎实：逐步推进、phase/tip/常见错误、自动倒计时（可暂停/继续/重置）、
  墙钟截止点切后台回来按真实时间扣减、计时中点返回弹窗拦截、语音到点提示、
  完成打卡上传成品照（`lib/pages/cook/cook_page.dart:19-20, 34, 40, 69-115, 171, 423-470, 818-851, 924`）。
- 计时口径统一：详情页 chip 与烹饪模式共用 `RecipeStep.explicitSeconds`
  （`recipe_step.dart:65-76`），修过"774 步有 duration 无 timer 却没计时器"的 bug（`cook_page.dart:75-77`）。
- **缺 1：屏幕常亮**。全库搜 `wakelock / wake_lock / keepScreenOn / 屏幕常亮` = 0 命中，
  pubspec.yaml 无 wakelock 依赖。
- **缺 2：命名计时器 / 多计时器并行**。全库搜 named timer / 命名计时 = 0 命中；
  当前是"当前步骤单一计时器"，不能同时给"炖锅 20 分钟 + 腌料 15 分钟"各起一个命名计时。
- 判为部分有：核心 cooking UX 有，标准里点名的两个特征各缺一个。

### 3. 份量缩放（公制 + 美制）—— 部分有
- 双单位：`Ingredient` 有 `qty / unitImperial / unitMetric / metricValue`，
  `quantityText({bool useMetric})` 按偏好出文本（`ingredient.dart:11-13, 106-116`）。
- 偏好落库：onboarding 第 8 题"I measure in..."写入 `measurement_pref`，
  主程序注入 `useMetricProvider`（`onboarding_page.dart:183-184, 255-256, 364, 455`；`main.dart:87`）。
- **缺：真正的份量缩放**。详情页只展示 `servingsBase` 静态人份
  （`recipe_detail_page.dart:264, 487`），配料表按 `quantityText()` 原值显示，
  无按 servings 倍数缩放用量的 UI/逻辑。购物清单页有 1-10 份量滑杆，
  但只用于成本与"锅具容量 ~4 人份分批"提示（`shopping_list_page.dart:173-208`），
  清单条目 `CartEntry.qty` 记的是"需要它的菜谱数"而非用量（`cart_provider.dart:14`）。
- 判为部分有：单位切换有，份量缩放没有。

### 4. 内置食材替换 —— 有
- 模型：`IngredientSubstitute` 含 substituteName / ratio / storeType / avoidsAllergens / notes
  （`lib/data/models/ingredient_substitute.dart:4-22`）；`Ingredient.substitutes` 与 `withSubstitutes()` 支持详情页 JOIN（`ingredient.dart:35, 123-155`）。
- UI：配料区"Swaps that work / 可这样替换"逐条列出替代名与比例（`recipe_detail_page.dart:842-850`）。

### 5. 食材/库存搜索 —— 有
- `FridgePage` 有 `TextEditingController` + 300ms 防抖 + `_query` 生效词
  （`fridge_page.dart:109-113, 221-224`），搜索框 placeholder 明确"搜索食材（中英文均可）"（`:965-981`）。
- `_findRecipes()` 按选中食材找菜谱（`:481-614, 894-901`）；
  大类/二级分组来自库表 `ingredient_category` + `ingredient_taxonomy.group_slug`（`:117, 170`）。
- 判为有：搜索 + 按库存反向找菜谱均实现。

### 6. 经过测试的菜谱 + 技巧视频 —— 部分有
- 技巧视频：`Lesson.videoUrl` 字段存在（`lesson.dart:16`），课程按 knife/heat/seasoning/timing 四维分类，
  content 含 why/key_points/common_mistakes（`lesson.dart:4-19, 86-105`）；
  `/lessons` 与 `/lesson/:slug` 路由齐（`app_router.dart:208-215`）。
- **缺 1：菜谱"经过测试"的证明**。Recipe 模型无 tested / test_count / verified 字段
  （`recipe.dart` 全字段），全库搜 tested/test_count/verified = 0 命中；
  只有 `dataSource='estimated'` 与 communityRatingCount（评分，非"开发者实测"）。
- **缺 2**：视频数据质量——`recipe_detail_page.dart:39` 注释记录 1475 行 video_url 指向同一 soup 视频，
  代码按"URL 必须能证明属于这道菜"才展示（`:1242-1259`），意味着实际可展示视频远少于字段数。
- 判为部分有：技巧课程内容有，菜谱测试标记没有。

### 7. 周计划 → 合并的按过道排序购物清单 —— 部分有
- 合并算法扎实：按食材名 lowercase 归一合并、qty 累加、sources 记来源菜谱，
  移除菜谱按来源递减到 0 自动消失（`cart_provider.dart:8-11, 106-162`）；
  登录用户同步 `shopping_lists` 表（`:80-103`）。
- **缺 1：周计划**。无 meal_plan / weekly 实体；`/events` 是"饭局"不是周计划
  （`app_router.dart:238-247`）；create_event_sheet 只有"今晚/明天/这周末/不定"（`create_event_sheet.dart:48`）。
- **缺 2：过道排序**。清单分区是"本店有价 / 另一店可找 / Asian aisle & other 按大类"
  （`shopping_list_page.dart:120-133, 235-275`），不是按超市过道顺序排列；
  `Ingredient.storeSection` 字段存在（`ingredient.dart:33`）但**未被清单页消费**。
- 判为部分有：合并有，周计划和过道排序没有。

### 8. 一键下单 —— 没有
- 只有联盟导流：每个条目的 `Buy at Walmart` / `Buy at Weee!` 外链，
  先写 `affiliate_clicks` 再跳带 UTM 的搜索页（`shopping_list_page.dart:68-110`）。
- 无购物车结算、无订单、无支付、无 SKU 匹配（清单 `CartEntry` 只有 name/qty/sources/category）。
- 课程带货同理是 affiliateUrl 外链（`lesson.dart:107-143`）。
- 判为没有：这是联盟返佣跳转，不是一键下单。

### 9. 学习型个性化 —— 部分有
- 有：8 题问卷（目标/份量/场景/辣度/忌口/技能/购物渠道/单位），
  辣度上限与技能等级喂软过滤（`onboarding_page.dart:13-16, 447-455`；
  `user_profile.dart:35-58` 的 effectiveMaxSpice / effectiveMaxDifficulty）；
  首页"为你推荐"（`home_page.dart:278-279, 426`）。
- **缺：学习闭环**。打卡/XP/技能树（cook_recipe 返回的 dimension=knife/heat/seasoning/timing，
  `community_rating.dart:94-99`）只记成长，不回流为推荐权重或口味画像更新；
  偏好只在问卷时写一次，无"根据你做过的菜/评分自动调整"的逻辑。
- 判为部分有：静态偏好过滤有，行为学习没有。

### 10. 可分享的文件夹/菜谱集 —— 没有
- 分享基础设施只覆盖三种单条实体：`ShareService.recipeUrl / eventUrl / communityPostUrl`
  （`share_service.dart:41-45`），七个渠道（短信/WhatsApp/邮件/Facebook/X/Pinterest/复制，`:6-16`）。
- 全库搜 collection / folder / 菜谱集 / bookmark = 0 命中（唯一 folder 是图片上传目录
  `PhotoUpload.folders`，`photo_upload.dart:26`）。无集合实体、无集合页、无集合分享链接。
- 判为没有。

### 11. 每道菜谱的社区证明 —— 有
- 评分：`CommunityRating` 色/香/味均分 + 综合分 + 评分人数（`community_rating.dart:4-40`），
  详情页 `_CommunityRatingSection` 展示（`recipe_detail_page.dart:401-411, 1608-1620`），
  有真实评分才写 JSON-LD aggregateRating，不伪造（`:1333-1341`）。
- 评论：`RecipeComment` 支持父子层级（`community_rating.dart:43-76`），
  `recipe_comments_section.dart` 有图文评论 + 上传（`recipe_comments_section.dart:91`）。
- 打卡证明：I made this 双轨（Quick Log / Rate & Review，`:222`），cook_photos 成品照
  （`cook_page.dart:818-851`），社区发帖（post_recipe_sheet）。
- 判为有：评分 + 评论 + 打卡 + 成品照四种证明齐。

### 12. 营养标准 —— 没有
- 全库搜 nutrition / calorie / kcal / protein / carbs / fiber / sodium = 0 命中
  （"protein"只作为食材大类标签出现在 fridge_page.dart:134，与营养无关）。
- Recipe 模型无营养字段（`recipe.dart:8-63`）：只有 dietTags / allergensContains /
  crossContaminationRisk / goalTags，属饮食限制而非营养数据。
- 判为没有。

### 13. 离线 —— 没有
- `web/manifest.json` 存在（standalone、图标齐），但只是 PWA 外壳。
- `web/index.html:104-110` 主动 `unregister()` 所有 service worker 并 `caches.delete()` 清缓存；
  `web/flutter_bootstrap.js:7` 与 `build/web/flutter_bootstrap.js:47` 均为 `serviceWorkerSettings: null`。
- 源码无 Hive/Isar/本地菜谱库，仅 SharedPreferences 存偏好与草稿（非内容离线）。
- 判为没有，且是**主动关闭**状态。

### 14. 慷慨免费层（付费墙锁深度，不锁做饭）—— 有
- 游客可读：`isPublicLanding()` 允许未登录只读 /recipe/、/event/、/community/post/
  （`app_router.dart:50-62, 153-155`），GuestBanner 只提示不挡内容（`guest_banner.dart:6-9`）。
- 免费额度：免费层开放 150 道组合、基础用户每晚 3 个推荐（`tonight_page.dart:13, 25, 224-225`）。
- 付费/门槛锁的是"深度"：课程 tier=xp/premium（`lesson.dart:54-64`）、
  技能树 premium 节点（`skill_tree_page.dart:141`）、组合数上限；
  做饭链路（烹饪模式、打卡、购物清单、分享）不收费。
- 判为有：符合"锁深度不锁做饭"。

### 15. 多设备 —— 部分有
- 服务端为准：问卷状态唯一事实源是 `users.onboarding_completed`，换设备登录校正
  （`app_router.dart:82-121`），并把 spice_pref / skill_level 带回本机（`:101-115`）。
- 上云：购物清单 `shopping_lists`（`cart_provider.dart:80-103`）、打卡/积分/XP 走 Supabase RPC
  （`lesson_detail_page.dart:63-97`）、社区内容、cook_photos。
- 部分仍只在本地：课程解锁 `unlocked_lessons`（`lesson_detail_page.dart:56, 76-78`，
  服务端有 spend_points 事务但本地仍需记住已解锁）、问卷草稿（`onboarding_page.dart:62, 73-98`）、
  匿名清单（LocalStorage，`cart_provider.dart:59-72`）。
- 判为部分有：账号态可跨设备，匿名/部分解锁态不可。

### 差异化：灶具 / 锅具适配（按灶火、锅具改步骤和火候提示）—— 没有
- 用户档案预留字段：`UserProfile.stoveType` / `cookware`（`user_profile.dart:17-18, 30-31, 81-82`）。
- 但问卷明确**不采集**："炉灶/锅具不再收集（spec §三：设备不放问卷）"（`onboarding_page.dart:252`）。
- 全库无消费点：搜 stoveType/cookware 只命中模型定义与 fromJson 两处，
  无任何"按灶火/锅具改步骤文案或火候"的逻辑；步骤只有统一 phase/tip/skillTag。
- 唯一相关是烹饪模式静态提示"锅具容量约 4 人份 → 分批"（`shopping_list_page.dart:196-206`），
  与标准要求的"按用户的灶具锅具动态改步骤和火候"不是一回事。
- 判为没有：**六家对标没做、我们只留了字段没做功能，独占机会仍是空的**。
